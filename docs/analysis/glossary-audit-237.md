# Glossary baseline audit — ticket 237

Completion record for [#237](https://github.com/markdlabrecque/sawmill/issues/237). Baseline: `3b4ea251b5f7a5428e82d45da79406040ef16b33` (before implementation). This is audit evidence, not a second glossary or maintenance procedure; the procedure is [domain.md](../agents/domain.md).

## Method and scope

Read every baseline entry in the root [GLOSSARY.md](../../GLOSSARY.md), including preferred names and all `_Avoid_` alternatives. Compared definitions with current types/operations, their tests, the spec, operating guide, role instructions and watcher skills. Dispositions below describe the actual editorial changes relative to that baseline: **retained** means definition and alternatives unchanged; **revised** identifies the correction. After rebasing onto `f0ca208a11f80b93b0c21c2b7252d2867d8e9c70`, Archive Section is removed: integration deliberately removed that Board feature in [#229](https://github.com/markdlabrecque/sawmill/issues/229). All other entries still name live Sawmill concepts. Obsolete claims inside entries were removed rather than preserving them as alternate definitions. The original audit evidence below is supplemented by the current Board evidence in the conflict resolutions.

The `_Avoid_` lists are vocabulary advice for naming domain concepts, not a ban on programming words or literal identifiers. This distinction is now explicit in the glossary and maintenance procedure: `backend`, `status`, `dependency`, `owner`, `worker`, `phase` and `provider` legitimately occur in code with different meanings. No API identifiers or tests were renamed to satisfy vocabulary advice.

Source paths below are repository-relative. `docs/specs/sawmill.md` supplies the overall domain, `docs/operating-mill.md` the current operational rules, and `docs/specs/live-view.md` the Board domain. Tests are supporting evidence, not the sole proof of this editorial audit.

## Conflict resolutions and evidence

- **Generic optional/multi-context instructions vs this repo's unconditional rule:** replaced `docs/agents/domain.md`'s optional-read, missing-file silence and deferred `/domain-modeling` advice with the single-context maintenance procedure. `AGENTS.md` points directly to root `GLOSSARY.md` and the procedure. No glossary map or duplicate procedure was introduced.
- **Six outcomes vs runtime seven:** added `test-correction` to Outcome, broadened Reviewer, and reconciled the spec's runtime-contract enumeration/reviewer story. `src/runtime.ts` and `test/test-correction.test.ts` establish the reviewer-only request, separate from implementation bounces. `no-change` is also now explicit in the spec enumeration.
- **Stage vs Phase, Slot vs Worker, Lane vs whole track:** glossary now distinguishes the concepts actually exposed by `src/config.ts`, `src/run-store.ts`, `src/dispatch.ts` and `src/view/model.ts`; removed the misleading blanket Phase/step avoidance. No runtime identifiers changed.
- **Archive removal during integration rebase:** the original audit corrected whole-run versus immediate done-ticket archiving. Integration commit `f0ca208` ([#229](https://github.com/markdlabrecque/sawmill/issues/229)) subsequently removed the Board archive, superseding that correction. Preserved integration's active-only Board definition, removed Archive Section rather than restoring it during conflict repair, and reconciled `docs/specs/live-view.md` stories, snapshot, page, reading and testing guidance with current `src/view/model.ts` and `test/archive.test.ts`. The Active Section includes inactive/stopped/paused runs but no done tickets or completed runs; saved history stays on disk and is not displayed. No runtime or test changes. The earlier unknown-stage lane clarification remains supported by `laneOf` and `test/view-page.test.ts`.
- **Invocation checkout vs designated Millyard; overwrite vs append:** reconciled spec Solution, Millyard, draft story and Draft implementation with `src/millyard.ts`, `saveDraft`, `test/project-cwd.test.ts`, `test/draft-append.test.ts` and the operating guide. No broadened replacement permission.
- **“Write-only tracker” vs actual reads:** reconciled spec Solution/State changes/Tracker mirror with glossary Tracker, refresh/reset and first-start/merge/mirror-recovery safety reads. Evidence: `test/ticket-refresh.test.ts`, `test/closed-tickets.test.ts`, `test/lost-response.test.ts`. The tracker still cannot supply run state.
- **“Blocker done” vs locally available merged work:** clarified spec Run file and readiness story to match `readRunFile` and the eight cases in `test/merge-readiness.test.ts`. Merge acceptance, fast-forward and remaining cleanup are not interchangeable.
- **Case list only / rerun failures only vs named headings and stale proof:** reconciled spec User testing and re-review story with `userTestSection`, `browserHandoff`, `roles/reviewer.md`, `test/user-testing.test.ts` and `test/browser-evidence.test.ts`. This is terminology/proof-documentation alignment, not a change to browser behavior.
- **Re-review “only” the fix vs broader-impact and assigned-case obligations:** revised Re-review to make narrow repair scope the default and link to `roles/reviewer.md`, rather than duplicate its detailed requirements. That role's What you get requires reviewing what schema, public-interface or shared-UI repairs can break beyond the old failure; User test cases independently requires exactly the assigned cases on every review. Supporting tests: `test/team.test.ts` (narrow repair re-review) and `test/browser-evidence.test.ts` (stale proof reruns). The earlier retained disposition missed this conflict; the revised definition preserves both obligations.
- **Hook only setup/teardown and Registry only after run:** corrected glossary to reflect prepare/notify hooks and build registration, already documented and tested in `test/worktree-prepare.test.ts`, `test/stop-diagnosis.test.ts` and `test/view.test.ts`.
- **Human Waiver vs watcher best-guess waiver:** retained the explicit human-decision boundary established by `src/acceptance.ts`, reviewer instructions and `test/acceptance-checklist.test.ts`. Corrected shared Watch playbook/destructive guidance and Nightwatch limits: no invented item, no autonomous waiver; Foreman escalates a needed decision, Nightwatch parks without asking. A watcher may execute an already authorized, item-specific human decision. Best-guess `approve-tests` guidance is unchanged. This resolves the contradictory guidance without changing runtime authorization or workflow code.
- **Watcher ledger/report vs learning ledger/retrospective:** clarified and added definitions from the shipped skills. Watchers can end with unresolved work; neither parking nor learning marks a run completed.

These resolutions use existing behavior and explicit instructions as evidence; no product intent is left unresolved by this audit, and no runtime enforcement was added.

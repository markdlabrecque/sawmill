Less babysitting.
More making.

The useful part of a factory is all the things you no longer have to remember.

Every ticket gets its own workbench.

Each ticket runs in its own Git worktree. Ready tickets can run in parallel, while blocked tickets wait their turn. One scheduler shares capacity across your projects.

The guardrails are part of the machine.

Test writers establish the failing tests. The implementer makes them pass. A separate reviewer checks the change. Sawmill protects the committed tests and controls the handoffs.

A logjam gets a limit, and a reason.

Review bounces and failed checks go back for repair. When the repair budget runs out, Sawmill stops that ticket and tells you what needs attention. No endless "one more try."

The process has a memory.

Run state lives on disk. Stage results, reports, and checkpoints remain inspectable when an agent's session ends. You can see what happened and where the ticket stands.

A few nuts
and bolts.

Does deterministic mean identical code every time?

No. The agents still reason and generate code. Sawmill makes the surrounding process explicit: which stage comes next, what evidence is required, when to retry, and when to stop. It does not promise identical output or bug-free software.

Can I still use skills and my own instructions?

Yes. Skills and instructions can guide the work inside a stage. Sawmill handles the lifecycle around that work, so a prompt is not the only thing standing between an unfinished change and a merge.

What actually gets merged, and where?

Sawmill merges onto the integration branch you configure. It requires valid review and passing local tests, plus successful CI when configured. Release promotion is a separate step.

What do I need to run it?

Node.js 22.13 or later, Git, Bash, an authenticated tracker CLI, and an installed, authenticated model CLI. Execution also requires TypeSafe configuration. The installation guide and operating guide cover setup. Automatic orphan recovery requires Linux.
